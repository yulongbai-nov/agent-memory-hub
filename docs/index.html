Shared, scoped memory across agent clients

This hub showcases how Graphiti (service + Neo4j), Copilot Chat (VS Code), and Codex CLI work together so that memories (preferences, terminology, ownership context) can be recalled across tools without per-client silos.

End-to-end architecture

Both clients ingest turns and curated “episodes” into Graphiti, and optionally recall facts (time-bounded) to inject into the next prompt. Shared memory happens when both clients compute the same canonical group ids.

Key idea: both clients compute the same canonical group ids from stable keys (user login + repo identity), so that a preference learned in one tool is recalled by the other.

What’s stored

  • Turns: user + assistant text (session/workspace)
  • Curated episodes: <graphiti_episode kind="preference">…
  • Ownership context: scope + owner + workspace basename
  • Recall: a bounded set of facts injected as <graphiti_memory>

Canonical identity + group ids

To share memory across clients, both tools derive the same keys and then hash them into a canonical group id.

  • User key: github_login:<login>
  • Workspace key: github_repo:<host>/<org>/<repo> (derived from git remote)
  • Canonical group id: graphiti_<scope>_<sha256(key)[:32]>
# Canonical group id formula (both clients)
graphiti_<scope>_<sha256(key)[:32]>

# Examples of keys
github_login:octocat
github_repo:github.com/octo-org/octo-repo

Note: current Graphiti deployment may not expose POST /groups/resolve; clients do not depend on it.

Why “canonical” fixes cross-tool silos

  • Before: Copilot Chat and Codex stored into different per-client group id namespaces, so recall never crossed tools.
  • Now: both write/read the same canonical graphiti_user_* and graphiti_workspace_* groups.
  • Migration: recall still queries legacy ids so older memories are not dropped.

Cross-client E2E demo (Copilot Chat + Codex)

Run this to prove shared user/workspace memories across tools.

  • Copilot Chat → Codex recall: promote a preference in VS Code, then ask in Codex.
  • Codex → Copilot Chat recall: promote a preference in Codex, then ask in VS Code.
# In Copilot Chat
preference (user): I prefer rg over grep for searches. marker: shared-memory-<timestamp>

# In Codex
What is my preference for searching in this repo?

Full walkthrough: docs/demos/e2e-shared-memory/README.md

What to look for

  • <graphiti_memory> injected as a system message (recall)
  • Canonical group ids (user/workspace) match across clients
  • Ingestion is async: wait ~5–15s after promotion
# Graphiti smoke: ingest → episodes → (optional) search
GROUP_ID="graphiti_smoketest_$(date +%s)"
NOW="$(date -Iseconds)"
curl -sS -X POST http://graph:8000/messages -H 'content-type: application/json' \
  -d "{\"group_id\":\"$GROUP_ID\",\"messages\":[{\"role_type\":\"system\",\"role\":\"system\",\"content\":\"smoke $NOW\",\"timestamp\":\"$NOW\"}]}"
curl -sS "http://graph:8000/episodes/$GROUP_ID?last_n=10"
